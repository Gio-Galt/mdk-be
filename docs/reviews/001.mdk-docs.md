## Review on the MDK Doc by Harrie

### Point #1
> @tetherto/mdk-client is the universal SDK, a connection library that applications use to talk to @tetherto/mdk-ork. It serves as a universal adapter: handling all the connection details so developers can focus on building their application. 

This is the library for calling the ORK. Essentially, "applications" here refers to the app-node plugins, which use this library to query the ORK and retrieve relevant data.
The understanding is not necessarily wrong, but the placement within the doc is incorrect — it should be covered under App-Node Plugin. Additionally, the term "universal" may no longer be accurate, as the FE communicates via a typical REST API protocol rather than MDL.

### Point #2
> MDK App Toolkit

The MDK solution is ORK + AppNode + Workers, along with the MDK Protocol for communication between AppNode <> ORK and ORK <> Workers.
The understanding here is not completely wrong, as it aligns with the original HLD. The idea is that the App Toolkit provides ways to build functionality on top of MDK. The AppToolkit consists of a Frontend Kit (i.e., the UI kit and other libraries for UI, state management, and React) and, on the backend, the AppNodePlugin architecture.
This hierarchy is not clearly conveyed and the structure needs to be improved.


### Point #3
The diagrams / flow chart are directly rendering mermaid, which does not look great as compared to standards open source docs.
